## Status

The supplied harness runs end to end with its three offline mock policies. The test suite now contains 14 tests, and all 14 pass. Each validation experiment used 40 synthetic cases, 5 runs per case, seed 0, and 10,000 case-cluster bootstrap replicates.

No OpenAI or Anthropic experiment was run. Neither API key nor either provider SDK was available in the execution environment. The values below are engineering controls generated by policies whose behaviour is fixed in `backends.py`. They are not empirical results about an LLM and must not be presented as paper findings.

## Limits before a real experiment

1. **No live-model evidence exists yet.** A provider smoke test must precede a main run, and each trajectory must be manually inspected before scaling.
2. **The implemented task differs from the later study plan.** This harness evaluates financial-statement basis selection. It does not implement accounts-receivable reconciliation, ledger writes, authorization checks, or pre-commit intervention arms.
3. **Stratum A is a constructed process-rule test.** Its needed years have no restatement, so `as_reported` and `restated` values are identical. Calling the use of the default basis a material defect therefore depends on the prespecified policy, rather than demonstrated harm. This weakens a claim about materiality.
4. **The pooled rate depends on the forced 50/50 stratum mix.** Report each stratum and define any target mixture before collection.
5. **The checker validates compliance with its encoded rubric.** Independent policy review and planted positive and negative controls are still needed to establish that the rubric captures the intended construct.
6. **The cost and escalation sections remain secondary.** Cost ratios and reviewer catch rates are assumptions. The mock escalation values are properties of the programmed policies.
